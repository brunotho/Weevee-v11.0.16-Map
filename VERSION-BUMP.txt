Weevee version bump
===================

When the user says to bump the version, follow this file. Do every step
in the same bump. Skipping any one causes mismatched copies in play.

Two local folders (IMPORTANT)
-----------------------------
The user keeps TWO copies side by side in the Steam Maps folder:

  1. Working copy:  ...\Assets\Maps\Weevee-v11.08-Map-main\
     This is the folder Claude Code / the editor is attached to. Its name
     is deliberately frozen at "v11.08" forever so the Claude Code project
     connection (and its memory) stays intact. NEVER ask the user to rename
     it, never move it, and never treat its name as a version mismatch.
     The real version lives in this file and in the map lua, not here.

  2. Play copy:     ...\Assets\Maps\Weevee-vX.Y.Z-Map-main\  (sibling)
     When the user wants to play the same version as others, they download
     the pushed release from GitHub (Download ZIP), which unpacks as this
     folder. It's a read-only snapshot of whatever was last pushed -- never
     edit it. Local work in the working copy is invisible to it (and to
     everyone else) until it's committed and pushed in a bump.

Both folders contain a "Weevee - vX.Y.Z.lua" map, so both show up in the
game's map list. Between bumps both carry the same in-game title, so the
list shows two identically named entries -- the working copy is the one
with unreleased changes.

GitHub repo name = zip folder name of the play copy. The agent CAN rename
the repo from here with `gh repo rename` (old URL redirects).

Current version: 11.0.15
Next version:    11.0.16  (set this as current after a successful bump)

Names for version X.Y.Z
-----------------------
In-game title:  Weevee Map X.Y.Z
Lua file:       Weevee - vX.Y.Z.lua
GitHub repo:    Weevee-vX.Y.Z-Map
Play folder:    Weevee-vX.Y.Z-Map-main  (created by the user's ZIP download)
Working folder: Weevee-v11.08-Map-main  (never changes, see above)

Agent steps (in order)
----------------------
1. Confirm the new version number with the user if they did not give one.
   Default next is the "Next version" line above.
2. Update in the map lua:
     print("Weevee Map X.Y.Z script loaded");
     WeeveeDbg("script loaded X.Y.Z");
     GetMapScriptInfo Name =
       [COLOR_HIGHLIGHT_TEXT] Weevee Map X.Y.Z [ENDCOLOR]
3. git mv the map lua:
     Weevee - vOLD.lua  ->  Weevee - vX.Y.Z.lua
4. Update this file: set Current version, set Next version (patch +1).
5. Commit ALL playable map changes in that bump (not only the rename),
   message focused on why, then push to origin.
6. gh repo rename Weevee-vX.Y.Z-Map
   then: git remote set-url origin https://github.com/brunotho/Weevee-vX.Y.Z-Map.git
   Do not change git config. Do not force-push. Do not --amend unless
   the commit protocol allows it.
7. Tell the user the new version is pushed and they can Download ZIP
   from https://github.com/brunotho/Weevee-vX.Y.Z-Map to get the new play
   copy (Weevee-vX.Y.Z-Map-main). They can delete the previous play copy
   folder. Do NOT ask them to rename or move the working folder.

Notes
-----
- The working folder's "v11.08" name is intentional and permanent.
- If the play copy's folder name does not match the version they agreed
  to play with others, they downloaded the wrong copy.
- Local uncommitted/unpushed edits are invisible to everyone else until
  step 5.
- Do not bump by only editing the in-game title.
